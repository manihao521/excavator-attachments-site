# KRATOR Frontend Design System

Read `docs/brand-guideline.md`, inspect `assets/styles.css`, and reuse established page patterns before creating new styles.

## Direction

- Present KRATOR as a premium industrial B2B manufacturer and attachment specialist.
- Use the established dark navy, engineering yellow, white, and steel gray tokens.
- Prefer real products, factory work, testing, packing, and jobsite imagery.
- Keep layouts structured, technical, restrained, and easy to scan.
- Use strong hierarchy, specification tables, proof modules, and direct quote actions.

Avoid startup SaaS styling, excessive gradients, decorative glass effects, cartoon illustrations, generic AI-looking imagery, oversized rounded cards, and unverified trust badges.

## Implementation Checks

- Keep desktop and mobile content equivalent and free of horizontal overflow.
- Use semantic controls, visible focus, sufficient contrast, and meaningful labels.
- Reserve image dimensions to prevent layout shift.
- Keep buttons and forms usable with touch and keyboard input.
- Extend existing tokens and components before adding one-off CSS.
- Do not redesign unrelated modules during a scoped change.

Verify representative desktop and mobile screenshots in local preview after the build.
